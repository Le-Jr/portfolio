# Assets

Checklist of every pixel-art asset for version 1. Display rules are in [STYLE_GUIDE.md](STYLE_GUIDE.md#pixel-art-rules).

Sizes marked "proposed" are not in the planning doc. They are chosen to scale cleanly by an integer factor; change them if the art needs it.

Where pixel art comes from, in order of cost (from the planning doc): free packs with a commercial-use license, self-made in a pixel-art editor, or a commissioned artist for the avatar. **Decision for version 1:** icons come from the free MIT-licensed set [pixelarticons](https://github.com/halfmage/pixelarticons), and everything else is self-made in a free pixel-art editor (for example Piskel or LibreSprite). A commissioned avatar can replace the self-made one later.

Notes:

- **Theme variants.** pixelarticons are inline SVG with `fill="currentColor"`, so they follow the theme through CSS and need no per-theme files. Bitmap assets (avatar, cartridges, map tiles) use palette colors that work on both backgrounds. If one doesn't, make a dark and a light PNG and switch them with `[data-theme]` CSS. A `<picture>` media query would not follow the manual toggle.
- **Open Graph image.** It is the one place where text inside an image is acceptable, since it is not site content. Keep the text to the name "LEANDRO JUNIOR", which is the same in both locales, so one image serves both. Its `alt` text is in [CONTENT.md](CONTENT.md#open-graph).
- **Avatar.** It may use more palette colors than the icons, but still only the 16 palette colors.

## Skill icons

### Decision: generic pixel glyphs, not brand logos

The planning doc proposed redrawing each technology's logo in pixel art by rasterizing [Simple Icons](https://simpleicons.org/) SVGs to 16×16 or 24×24 in a palette color. Checking the brand rules (October 16, 2026) showed that most of the brands in the inventory **forbid modifying or recoloring their logos**. Pixelating and recoloring is exactly that. Some also forbid any logo use without written permission.

| Brand | What its rules say | Pixelated logo OK? |
| --- | --- | --- |
| Salesforce (B2B Commerce, Apex, LWC, SOQL) | "You may not alter or modify any of Salesforce's trademarks in any way"; most uses need written permission; no designs that borrow elements of its marks. Also not in Simple Icons at all. | No |
| Next.js (Vercel) | "Do not modify the Vercel marks"; uses beyond describing their products need written permission | No |
| Shopify | Use must be "expressly authorized in writing"; no custom versions or colors | No |
| WooCommerce | "You may not use the WooCommerce and Woo logos for any purpose" | No |
| PostgreSQL | "The marks should not be modified in any way without prior approval" | No |
| MongoDB | May not "edit, change, distort, recolor, or reconfigure" the marks | No |
| Supabase | Brand elements "can never be modified" | No |
| WordPress | Commercial use only "to refer to and explain their services"; silent on modification | Unclear |
| Node.js (OpenJS Foundation) | Points to the OpenJS trademark policy; not reviewed in detail | Unclear |
| Tailwind CSS | No implied endorsement; silent on modification | Unclear |
| Vue.js | Logo is CC BY-NC-SA 4.0, and the Vue team explicitly allows it "in portfolios, resumes, and personal websites" | Yes (attribution + share-alike) |
| React, NestJS, Prisma, shadcn/ui | No published rules found | Unknown |

Every brand **name** can still be written as plain text to describe experience; Salesforce and WooCommerce say so explicitly.

So, in version 1, each inventory slot shows a **generic pixel glyph** that hints at what the tool does, with the item name as HTML text under it. No logos. This:

- removes the trademark risk for all 20 items at once,
- keeps the inventory visually consistent (mixing a few real logos with generic glyphs would look uneven),
- needs no build script and no image files, since the glyphs come from pixelarticons, a set drawn on a strict 24×24 pixel grid.

To revisit later: pixel logos could return item by item if a brand grants written permission. Vue already qualifies.

### Source: pixelarticons

- Package: `pixelarticons` **2.4.2** (pinned), MIT, by Gerrit Halfmann. Ships React components (`pixelarticons/react`) that render inline SVG with `fill="currentColor"`.
- This is the one runtime dependency these docs pre-approve (see [AGENTS.md](../AGENTS.md#dependencies)). Import icons one by one so unused icons are tree-shaken.
- Do **not** use the brand icons that pixelarticons itself includes (`react`, `vercel`, `github`, `linkedin`, `discord`, and so on), for the same trademark reasons.
- Keep the MIT notice: credit it in the footer credits and in the licensing log below.
